# M4 評估：注音中英混打

> **狀態：A（快捷鍵英文暫存模式）已實作**，預設快捷鍵 `Ctrl+Shift+Space`（`Ctrl+Shift+E` 已被 Ghostty 的分割視窗佔用），詞表採選項 C（SCOWL 內建 + 使用者自訂）。用法見 `PLUS.md`。
>
> 結論先講：**不建議做 WowType 那種「自動判斷」的中英混打**。
> 建議改做「**快捷鍵切換的英文暫存模式**」，加上「**失敗時才提示**」的低干擾輔助，兩者都預設關閉。

## 1. 為什麼注音不能照搬拼音的做法

拼音輸入法打 `github` 時，`g-i-t-h-u-b` 本來就不是合法的拼音音節串，所以引擎能直接判斷「這是英文」。
注音完全不同：鍵盤上**每個英文字母都對應一個注音符號**，打英文字母時，引擎看到的永遠是「一串合法的注音按鍵」。

我用小麥實際的鍵盤排列程式碼和詞庫量測（Google 前 10,000 常用英文字，`scripts/` 外的一次性評估程式，不進產品）：

| 量測 | 結果 | 意義 |
|---|---|---|
| 英文字全部由注音鍵組成 | **100%**（9,474/9,474，≥3 字母） | 不可能靠「有沒有非注音鍵」來判斷 |
| 打英文字時中途遇到「組不成字」的音節 | **0%** | 標準排列下聲調鍵是 `3 4 6 7`，字母永遠不會觸發組字，所以「組字失敗」這個訊號完全不存在 |
| 英文字母串「剛好」是合法的一聲音節（按空白就變中文） | 標準 0.35%、倚天 0.50%、**許氏 1.2%** | 例如 `no`=ㄙㄟ、`up`=ㄧㄣ、`be`=ㄅㄧ、`to`=ㄊㄡ、`my`=ㄇㄚ；這些是最常用的英文字 |
| 「按鍵會覆蓋前一個注音成分」的英文字比例 | 標準 98.9%、許氏 97.7%、倚天26 97.4% | 例如 `the`：ㄔ→ㄘ→ㄍ（聲母被連續蓋掉兩次）。真正打注音的人幾乎不會這樣打 |

最後一列是唯一可用的訊號：正常打注音是「聲母→介音→韻母→聲調」依序打，**不會重複打同一類成分**；英文字則幾乎一定會。
但這個訊號有兩個問題：

1. **它只在「打到一半」才出現**。`the` 打 `t` 時是合法的 ㄔ，打到 `h` 才變成「ㄘ 蓋掉 ㄔ」，引擎得等到後面才知道，前面的字母已經被當成注音顯示了。
2. **打錯注音的人也會觸發**。快速打字時多按一個韻母鍵、想改聲母直接打新的聲母，在原版小麥都會被當成「覆蓋」，這正是很多人依賴的修正方式。若把它判成英文，會讓原本的行為改變——這違反 Plus「不改變正常輸入」的原則。

所以「自動判斷」最好的情況是 ~99% 準確、但錯的那 1% 會把**中文變成英文**，而且錯在最常用的字上（no、up、to、be、my）。對每天打很多中文的人來說，這比不支援還糟。

## 2. 建議做法

### A. 快捷鍵切換「英文暫存」模式（推薦，主要做法）

- 按一個快捷鍵（建議 **`Shift` 單按**，可自訂，例如 `Ctrl+Shift+E` 或右 `Shift`）進入英文暫存：組字區顯示 `[EN] github`。
- 期間打的字母**不經過注音**，直接進暫存區；下方候選列出英文詞表比對結果，讓 `github` → `GitHub`、`iphone` → `iPhone` 這類大小寫自動修正。
- 按 **空白** 上屏英文並自動切回注音；`Enter` 上屏原樣；`Esc` 取消；再按一次快捷鍵也切回。
- 會跟目前的中文組字區接在一起：`你好` + `[EN] linux` + 空白 → `你好 Linux`（配合已有的中英自動空格）。

優點：**完全不猜**，零誤判、不影響正常注音；比切換整個輸入法（`keyboard-us` ↔ 小麥）快，而且不打斷中文組字區。
這也是微軟注音、新酷音的 Shift 切換在使用者心中的模型，學習成本低。

注意：fcitx5 全域的 `AltTriggerKeys` 預設就是 `Shift_L`（你的 `~/.config/fcitx5/config` 裡沒有改它，所以是生效的），用途是「暫時切回第一個輸入法」。若用左 `Shift` 當切換鍵會和它搶按鍵，所以預設建議用**右 `Shift`**，或到 fcitx5 全域設定清掉 `AltTriggerKeys`。

### B. 「失敗才提示」的輔助（選用，預設關）

在**不改變任何行為**的前提下，用前面量到的「覆蓋」訊號做提示：

- 偵測到疑似英文（例如連續 ≥4 個按鍵、出現 ≥2 次成分覆蓋、且字母串在英文詞表中）時，只在組字區旁顯示一個小提示「`⇧` 切成英文 → GitHub」，**不自動轉換**。
- 使用者按快捷鍵才會把剛剛那串按鍵轉成英文（回溯轉換），否則照原本的注音行為走。

這樣誤判的代價只是「多一個提示」，而不是「中文被吃掉」。

### C. 不建議

- **自動判斷並直接轉英文**（WowType 拼音做法）：理由見第 1 節。
- **按空白時若是英文就上屏英文**：`no`、`to`、`my` 等常用字會直接誤判。

## 3. 英文詞表

- 需要「詞 + 正確大小寫」，例如 `GitHub`、`iPhone`、`macOS`。
- 候選來源：rime-ice 的 `en_dicts`（WowType 用的，GPL-3.0，需確認授權相容）、或 SCOWL/hunspell en_US（寬鬆授權）。我量測用的 Google 10k 詞表是 LDC 授權、**不能放進產品**，只用於評估。
- 使用者可在 `~/.local/share/fcitx5/mcbopomofo/plus-english.txt` 自訂（公司名、產品名）。

## 4. 建議實作順序

1. A：快捷鍵 + 英文暫存 + 詞表大小寫修正（約 1 個工作階段，含測試）。
2. B：失敗才提示（A 完成並用一陣子後再決定要不要做）。
